# A-02 邮件通道配置与排查

> 对应验收项 **A-02：真实邮箱收到验证码，验证后账号可用**。
> 代码侧已就绪（`src/lib/mailer.js`，零依赖 + 可选 `nodemailer`），差的只是服务商凭据能不能用。

---

## 一、配置在哪

`.env`（**已在 `.gitignore`，严禁提交**）。服务启动时由 `src/lib/env.js` 自动读取；
命令行/容器里已有的环境变量优先，不会被 `.env` 覆盖。

```ini
SMTP_HOST=smtp.qq.com
SMTP_PORT=465
SMTP_USER=你的邮箱@qq.com
SMTP_PASSWORD=授权码（不是登录密码）
MAIL_FROM=湘寻 <你的邮箱@qq.com>
PUBLIC_BASE_URL=https://你的公网地址
```

- 端口 **465 = SSL**，**587 = STARTTLS**，两者不要混
- `MAIL_FROM` 的邮箱必须与 `SMTP_USER` 一致，否则 QQ/163 会拒发
- `PUBLIC_BASE_URL` 决定邮件正文里是否带站点链接（非 http(s) 时自动省略）

## 二、三家服务商对照

| 服务商 | HOST | PORT | 密码类型 | 开启位置 |
|---|---|---|---|---|
| QQ 邮箱 | `smtp.qq.com` | 465 | **授权码** | 设置 → 账户 → POP3/SMTP 服务 |
| 163 邮箱 | `smtp.163.com` | 465 | **授权码** | 设置 → POP3/SMTP/IMAP → 开启并获取授权码 |
| Gmail | `smtp.gmail.com` | 465 | **应用专用密码** | 账号安全 → 两步验证 → 应用专用密码 |
| 阿里云邮件推送 | `smtpdm.aliyun.com` | 465 | 独立 SMTP 密码 | 控制台创建发信地址 |

**换服务商只改 `.env` 四个值，代码不动。**

## 三、验证三步

```powershell
# ① 只查配置是否完整（不发信）
node scripts/mail-check.mjs

# ② 真发一封
node scripts/mail-check.mjs 收件邮箱@example.com

# ③ 看服务端状态（演示前必做）
curl http://127.0.0.1:3000/health
```

`/health` 里的 `mail` 字段：

```json
"mail": { "configured": true, "attempts": 3, "delivered": 2, "failed": 1,
          "lastResult": "delivered", "lastAt": "2026-11-21T06:38:15.576Z", "lastError": null }
```

**`lastResult` 就是"最近一次发信成没成"**，比翻日志快。

## 四、故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| `535 Login fail` | ① 填了登录密码 ② 授权码被重置/停用 ③ **短时间发信太频繁被频控** ④ 账号异常被限制 | 按顺序排查；**别连发**，等 10-30 分钟；去网页版看是否有"异常登录"提示 |
| `ECONNREFUSED` / 超时 | 端口错、或者出网被封 | 465 换 587 试；确认服务器/网络允许出站 SMTP |
| 返回 `messageId` 但收不到 | 收件方拒收/判垃圾/发件人=收件人 | 查垃圾箱；**换一个收件地址**再试；检查 SPF/DKIM（企业邮箱） |
| `nodemailer_missing` | 依赖没装 | `npm install`（注意 npm 缓存目录要在可写位置） |
| `smtp_not_configured` | `.env` 没被读到 | 确认 `.env` 在项目根目录；`XF_NO_DOTENV` 没被设成 1 |

### 关于"发件人 = 收件人"

用同一个邮箱给自己发验证码，**很容易被反垃圾规则丢掉**——QQ 尤其明显。
排查时务必**换一个不同域名的收件地址**，否则分不清"通道坏了"还是"自发信被过滤"。

## 五、发信失败时的兜底

代码里有三层保护，按顺序生效：

| 情况 | 行为 | 用户看到 |
|---|---|---|
| 没配 SMTP | 验证码打进日志 `[mail:dev]` | 接口 `codeSent:false`，前端应提示"发送失败" |
| 配了但发不出去 | 验证码打进日志 `[mail:fallback] to=... code=XXXXXX` | 同上 |
| 发出去了 | 正常投递 | `codeSent:true`，前端提示"验证码已发送" |

**演示现场救急**：邮件通道挂了，从服务端日志里取 `[mail:fallback]` 那行的 6 位码，继续演示。
这比卡在验证页强，也比临时改代码安全。
