## 一、这是什么

**湘寻（XiangFind）** —— 湘潭大学校园失物招领平台。响应式 Web 应用，
学生发布失物/招领、系统做规则型智能匹配、志愿者在存放点核实与归还、管理员维护数据。

技术栈：Node.js 26（内置 `node:sqlite`）+ 原生 HTML/CSS/JS，**零外部运行依赖**。

---

## 二、怎么跑起来

```powershell
npm install                      # 只有一个依赖（nodemailer，可选）
Copy-Item .env.example .env      # 填 SESSION_SECRET（不填会启动失败，故意的）
npm run db:migrate               # 建表
npm run db:seed                  # 演示数据
npm start                        # → http://localhost:3000
```

### 关于 A-01：三条路都准备好了

| 方案 | 耗时 | 前提 |
|---|---|---|
| A. Ubuntu 服务器 + 一键脚本 | ~15 分钟 | 服务器 + 域名 |
| B. Cloudflare 隧道 | ~10 分钟 | 本机常开 |
| C. 同一 Wi-Fi 局域网 | 1 分钟 | 零成本兜底，但不满足 A-01 的"校外访问" |

**C 不算 A-01 通过**——它只能证明"手机上真能用"，不能证明"校外能访问"。
这一点会如实写在验收结论里，不会含糊过去。

## 七、已知限制（设计取舍，非缺陷）

| 项 | 说明 |
|---|---|
| 匹配算法 | 规则加权，**不是机器学习**。理由：数据量小、结果可解释、用户能追问"为什么匹配" |
| 中文分词 | 字符二元组 + 停用词，未引 NLP 库 |
| 地点匹配 | 不建地名词典，靠前缀与关键词重合（D-002） |
| 限流 | 进程内存实现，单实例有效；多实例需换共享存储 |
| 会话 | DB 存储，重启不掉线；改密码会踢掉所有会话 |
| 数据库 | SQLite 单文件，2000 条时 p95 约 3ms；再大换 PostgreSQL（数据层已隔离） |
