## 2. 项目范围与成功标准

### 2.1 项目定位
湘寻是面向湘潭大学的校园失物招领 Web 平台。学生可以发布失物与招领信息、搜索和智能匹配、提交认领申请，并通过站内消息接收处理结果。志愿者具有公开可见的身份徽章，在招领点协助核实和归还物品；管理员负责志愿者授权、存放点维护、认领处理和数据管理。

### 2.2 本期必须完成
- 公共互联网 HTTPS 访问，电脑和手机浏览器均可用。
- 学号或用户名加密码登录，邮箱验证码绑定和找回密码。
- 学生、志愿者、管理员三类角色；保卫处角色按暂定方案处理。
- 失物和招领发布、图片上传、分类、地点、时间、描述、贵重等级和存放点。
- 所有招领物品必须记录存放地点；贵重物品必须选择保卫处类型存放点。
- 关键词搜索、类型/分类/状态筛选、详情、收藏。
- 规则型相似信息智能匹配，展示匹配分数和原因。
- 认领申请、发布者及管理角色确认、领取通知和归还记录。
- 站内消息中心、未读数量、关键节点通知。
- 管理员用户管理、志愿者授权、存放点维护、申请审核、统计和数据恢复。
- 联系方式默认隐藏，认领通过后按规则显示。

### 2.3 本期不做
- 微信小程序、原生 Android/iOS 客户端。
- 支付、短信验证码、微信订阅消息。
- 实时聊天、视频通话、地图导航。
- 付费 AI 图片相似度或大型模型接口。
- 保卫处独立管理后台已列为可选事项，不能影响学生、志愿者和管理员主流程。

## 4. 功能需求

### 4.1 注册、登录与邮箱验证
- 注册字段：姓名、学号、邮箱、密码、确认密码。学号和邮箱都必须唯一。
- 邮箱发送 6 位验证码，有效期 15 分钟；同一邮箱 60 秒内不能重复发送，每天最多 10 次。
- 验证码必须哈希后存储，校验成功后创建账号或完成邮箱绑定。
- 密码使用 Argon2id；若运行环境不支持，则使用 bcrypt cost 12。禁止明文和可逆加密。
- 登录成功使用 HttpOnly、SameSite=Lax 的会话 Cookie；会话 7 天有效，退出时销毁。
- 支持通过已绑定邮箱重置密码。
- 现有账号首次登录后必须完成邮箱绑定，未绑定账号不能发布或认领。
- SMTP 服务商账号：目前暂定，以后再考虑。开发环境可以把验证码写入服务端日志，生产环境必须真实发送。

### 4.2 失物与招领发布

| 字段 | 要求 | 说明 |
|---|---|---|
| 类型 | lost 或 found，必填。 | 失物表示自己丢失；招领表示自己捡到。 |
| 标题 | 1-60 字，必填。 | 不得只填写“东西”等无法识别的标题。 |
| 分类 | 必填。 | 证件、电子产品、钥匙、书籍、衣物、其他。 |
| 描述 | 1-500 字，必填。 | 描述颜色、品牌、时间、特征和可核对细节。 |
| 发生地点 | 1-80 字，必填。 | 例如“图书馆三楼自习区”。 |
| 发生时间 | 可选，不得晚于当前时间。 | 用于匹配和展示。 |
| 图片 | 最多 3 张，单张不超过 5MB。 | 仅允许 JPEG、PNG、WebP；服务端必须校验真实文件类型。 |
| 贵重等级 | 招领必填，normal 或 valuable。 | 由发布者选择；志愿者或管理员可以确认或纠正。 |
| 存放点 | 招领必填。 | 普通物品选择普通存放点；贵重物品只能选择保卫处类型存放点。 |
| 联系方式 | 从用户资料读取，不直接公开展示。 | 认领通过后显示给双方。 |

### 4.3 浏览、搜索与筛选
- 首页默认按“进行中优先、发布时间倒序”展示。
- 支持关键词搜索标题、描述、地点和分类；支持类型、分类、状态、贵重等级和存放点筛选。
- 物品卡片展示类型、状态、标题、摘要、分类、地点、时间、发布者和志愿者徽章（若有）。
- 详情页展示完整描述、图片、匹配结果、存放点、申请入口和处理记录。
- 支持收藏和取消收藏；收藏内容在个人中心查看。

### 4.4 物品状态

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| pending_storage | 招领物品尚未确认入库。 | 由志愿者、管理员或保卫处确认后变为 stored。 |
| stored | 物品已存放，可匹配和申请认领。 | 学生提交申请，状态变为 claim_pending。 |
| claim_pending | 至少有一条待审核申请。 | 发布者、志愿者、管理员或保卫处确认归属。 |
| ready_for_pickup | 认领通过，等待现场领取。 | 现场核对后变为 returned。 |
| returned | 已完成归还。 | 归档，不允许新申请。 |
| archived | 人工关闭或超期未处理。 | 仅管理员可恢复或永久保留记录。 |

### 4.5 认领流程
1. 失主在详情页提交认领申请，填写物品特征、丢失经过和可核对信息。
2. 系统向发布者、所属存放点志愿者和管理员写入站内消息。
3. 发布者可以参与确认；志愿者、管理员或保卫处在授权范围内可以最终确认。
4. 确认通过后，物品状态变为待领取，系统发送领取地址、开放时间和领取提醒。
5. 一条物品只能有一条通过申请；其余待处理申请自动拒绝并记录原因。
6. 现场领取时由志愿者或管理员点击“完成归还”，记录完成时间。
7. 联系方式在确认通过后才向认领双方展示。

### 4.6 志愿者身份
- 管理员按学号或邮箱搜索学生账号，添加或移除志愿者身份。
- 志愿者可以绑定一个或多个存放点；未被分配的存放点不可操作。
- 志愿者徽章在物品卡片、详情页和个人资料中公开显示。
- 志愿者本身仍是学生账号，不能管理用户、存放点或恢复数据。
- 志愿者可以确认物品入库、参与认领核实、确认归还。

### 4.7 存放点和贵重物品
- 管理员新增和编辑存放点：名称、类型、地址、开放时间、联系人、联系电话、备注、是否启用。
- 类型为 normal 或 security；security 代表学校保卫处。
- 发布招领时必须选择启用中的存放点；选择 valuable 时接口强制校验存放点类型为 security。
- 所有招领信息在详情中展示存放地点。
- 存放点地址由管理员输入，代码中不得硬编码学校真实地址。
- 实际存放点清单：目前暂定，以后再考虑。开发时先使用演示数据，管理员可以在后台替换。

### 4.8 站内消息
站内消息是本期唯一通知渠道。消息写入数据库，用户可以在消息中心查看并标记已读，导航栏显示未读数量。消息不得包含完整邮箱或密码等敏感信息。

| 触发事件 | 接收人 | 消息摘要 | 是否重要 |
|---|---|---|---|
| 认领申请提交 | 发布者、所属志愿者、管理员 | 有人申请认领某物品。 | 是 |
| 认领审核通过 | 申请人、发布者 | 申请已通过，请按地址领取。 | 是 |
| 认领被拒绝 | 申请人 | 申请未通过，可查看原因。 | 是 |
| 物品已存放 | 发布者、关注用户 | 物品已进入某存放点。 | 否 |
| 匹配度达到 70 | 失物和招领双方 | 发现一条高相似度信息。 | 是 |
| 管理员添加志愿者 | 被授权用户 | 你已成为志愿者。 | 是 |
| 物品超期未领取 | 申请人和管理员 | 请尽快处理领取。 | 是 |

### 4.9 个人中心
- 个人资料：姓名、学号、邮箱、联系方式、志愿者徽章和绑定状态。
- 我的发布：查看状态、处理申请、编辑未完成物品、标记完成。
- 我的申请：查看待处理、已通过、已拒绝和领取状态。
- 我的收藏：查看已收藏物品并取消收藏。
- 消息中心：全部、未读、系统消息和认领消息。

### 4.10 管理员后台
- 概览：用户数、物品数、进行中、待存放、待审核、已归还、未读消息。
- 用户管理：搜索用户、查看状态、添加/移除志愿者、重置密码或停用账号。
- 存放点管理：新增、编辑、启停、排序，并查看关联物品。
- 物品管理：筛选、编辑、归档、纠正贵重等级。
- 申请审核：查看详情、通过、拒绝、记录原因。
- 消息和数据：发送系统消息、恢复演示数据、导出统计。
- 所有管理操作写入 audit_logs，保留操作者、时间、对象和变更摘要。

### 4.11 联系方式与隐私
- 广场和详情默认隐藏完整邮箱、电话、QQ 和微信。
- 申请待处理时，只显示联系人姓氏或“已隐藏”。
- 申请通过后，向申请人和物品发布者展示联系方式。
- 志愿者和管理员只在处理当前物品时查看联系方式。
- 日志中不得记录密码、验证码、完整会话 Cookie 或完整联系方式。

## 6. 核心业务流程

**图 1  物品存放、匹配、认领与归还流程**

### 6.1 发布招领物品
1. 学生选择“招领”，填写标题、分类、描述、地点和图片。
2. 学生选择 normal 或 valuable；valuable 只能关联 security 存放点。
3. 服务端校验字段、文件、贵重等级和存放点类型。
4. 创建物品，状态为 pending_storage。
5. 向相关志愿者写入待确认存放消息。

### 6.2 确认存放
1. 志愿者、管理员或保卫处在授权范围内打开物品详情。
2. 确认实物、存放点和贵重等级。
3. 服务端写入存放确认记录，状态改为 stored。
4. 触发智能匹配，并给匹配对象写消息。

### 6.3 认领和归还
1. 失主提交认领说明，状态改为 claim_pending。
2. 发布者和授权角色可以查看申请，但不能看到未通过申请的完整联系方式。
3. 确认通过后状态改为 ready_for_pickup，自动拒绝其他待处理申请。
4. 系统给申请人发送存放地址、开放时间和领取提示。
5. 现场领取后，志愿者或管理员确认归还，状态改为 returned。

## 7. 智能匹配设计
第一期使用可解释的规则评分，不接入付费大模型或图片识别。匹配只发生在 lost 与 found 之间，双方状态必须为进行中或已存放。每新增、编辑或确认存放一条信息时重新计算。

| 维度 | 分值 | 计算规则 | 展示原因 |
|---|---|---|---|
| 分类 | 25 | 完全相同得 25，同大类得 10，否则 0。 | 分类一致 |
| 地点 | 20 | 地点文本相同或包含相同关键词得 20；同区域得 12。 | 地点相近 |
| 时间 | 20 | 发生时间相差 2 小时内得 20，24 小时内得 15，72 小时内得 8。 | 时间接近 |
| 关键词 | 25 | 对标题和描述分词，按重合关键词比例给分。 | 描述关键词重合 |
| 贵重等级 | 10 | 一致得 10，valuable 对 normal 得 0。 | 保管等级一致 |
| 阈值 | - | 总分 45 以上进入候选；70 以上发送站内消息。 | 推荐原因解释 |


**表 8  智能匹配评分规则**
- 每条物品最多保留 5 条候选匹配，按分数降序。
- 匹配记录保存 score、reasons JSON、created_at 和双方 item_id，重复计算时更新而非重复插入。
- 管理员后台提供“重新计算匹配”按钮，便于数据修正后刷新。
- 中文分词可以采用轻量的字符二元组和停用词策略，避免引入大型 NLP 依赖。
- 图片相似度目前暂定，以后再考虑；不得在本期引入付费云视觉 API。

## 8. 数据模型

| POST /api/auth/logout | 退出 | 登录用户；销毁会话。 |
| POST /api/auth/forgot-password | 发送重置邮件 | 公开；防止邮箱枚举。 |
| POST /api/auth/reset-password | 重置密码 | 使用一次性 token。 |
| GET /api/items | 列表和筛选 | 登录用户；不返回完整联系方式。 |
| POST /api/items | 发布物品 | 学生、志愿者；校验存放点和贵重等级。 |
| GET /api/items/:id | 详情 | 登录用户；按角色返回申请信息。 |

## 10. 技术架构与部署

### 10.1 技术选型
- 运行环境：Node.js 当前稳定版；建议锁定 package-lock.json，避免部署环境漂移。
- 服务端：沿用现有 Node.js HTTP 服务，按需引入 Express 或 Fastify；不得为了“最新技术”重写成未经验证的框架。
- 数据库：better-sqlite3 或 Node 内置 SQLite，使用参数化 SQL，禁止字符串拼接查询。
- 前端：保留现有 HTML/CSS/JavaScript 单页应用结构，按模块拆分 app.js。
- 邮件：Nodemailer + SMTP，配置通过 .env 注入。
- 图片：本地上传目录，文件名为随机 UUID；数据库只保存相对路径和元数据。
- 测试：Node 内置 test runner 做数据库与服务测试，Playwright 做浏览器主流程测试。

### 10.2 当前代码改造顺序
1. 把 data.json 读写替换为 SQLite repository，保留一次性迁移脚本。
2. 拆分 server.js：auth、items、claims、messages、matching、admin、static 七个模块。
3. 加入 CSRF、限流、输入校验和审计日志中间件。
4. 前端增加邮箱验证、志愿者徽章、存放点、消息中心和管理页面。
5. 补全错误处理、空状态、加载状态和移动端布局。
6. 部署到公网服务器，启用 HTTPS 和健康检查。

### 10.3 公网部署
公网访问已确认，但服务器和域名：目前暂定，以后再考虑。推荐使用一台 Ubuntu 云服务器，Nginx 反向代理 Node 服务，Certbot 或云证书提供 HTTPS，systemd 管理进程。服务器必须提供持久化磁盘，不能部署到无持久化文件系统的临时容器。部署前准备 PORT、DATABASE_PATH、SESSION_SECRET、SMTP_HOST、SMTP_PORT、SMTP_USER、SMTP_PASSWORD、MAIL_FROM、PUBLIC_BASE_URL。
- 每日备份 SQLite 文件、上传目录和 .env 配置（配置单独加密保存）。
- 保留最近 7 个日备份和 4 个周备份。
- 提供 /health 只返回服务、数据库和磁盘状态，不暴露敏感信息。
- 部署完成后用校外网络和手机流量各验证一次。
