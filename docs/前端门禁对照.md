# 前端门禁对照表（前端判断 ↔ 后端校验）

> **用途**：前端任何"什么情况下显示按钮 / 允许操作"的判断，都必须能指出后端对应的校验代码行。
> 说不出在哪一行的，就是**凭印象写的**——#94 那个 bug（`CLAIMABLE` 写错）就是这么来的。
>
> 维护方式：改了后端校验，来这张表里找对应的前端判断；改了前端判断，来这张表核对后端。
> 最后核对：2026-11-21（`main = 3521e23`）

---

## 一、物品相关

| 前端判断 | 后端校验位置 | 规则 |
|---|---|---|
| 显示「申请认领」按钮<br>`canClaimItem(item)` | `src/services/claims.js:48,52,54,67` | ① 必须是 `found` ② 不能是自己发的 ③ 状态只能是 `stored` / `claim_pending` ④ 同一人同物品只能有一条 pending |
| 显示「确认已入库」按钮<br>`canStore` | `src/services/items.js:321-323,349` | 管理员 / 所属点志愿者 / 保卫处（仅 security 点）。**发布者本人也不行**（需求基线 §3） |
| 显示「确认已归还」按钮<br>`ready_for_pickup && claim.canReview` | `src/services/claims.js:142` + `items.js:173-178` | 物品状态必须是 `ready_for_pickup`；操作者必须是所属点志愿者/管理员/保卫处 |
| 显示「编辑 / 下架」 | `src/services/items.js:324-334` | 发布者本人或管理员；已入库后关键字段锁定（管理员可改） |
| 详情显示「联系方式」卡片<br>`item.contact !== null` | `src/services/items.js:171-179` | 物品状态为 `ready_for_pickup` / `returned` **且** 请求者是发布者或已通过认领的申请人 |
| 收藏星标可点 | `src/services/items.js`（favorite） | 必须登录；切换语义（再点一次取消） |

## 二、认领相关

| 前端判断 | 后端校验位置 | 规则 |
|---|---|---|
| 显示「同意（agree）」 | `src/services/claims.js:121` | **只有发布者**能表态 |
| 显示「最终通过（approve）」 | `src/services/claims.js:141` | **只有所属点志愿者 / 管理员 / 保卫处**能终审 |
| 「拒绝」按钮 | `src/services/claims.js:121,141` | 发布者点 = 发布者拒绝（物品退回 `stored`）；审核者点 = 审核拒绝。**同一个 `reject` 按角色分流** |

| 认领通过后其余申请 | `src/services/claims.js:172` | 自动拒绝并通知 |

## 三、消息相关

| 前端判断 | 后端校验位置 | 规则 |
|---|---|---|
| 消息列表（全部/未读/分类） | `src/api/index.js:401-407` | 只能看自己的消息（`WHERE user_id = ?`）；`unreadCount` 同样只算自己的 |
| 标记已读 | 同上（`/api/messages/:id/read`） | 只能标记自己的消息 |

## 四、后台相关

| 前端判断 | 后端校验位置 | 规则 |
|---|---|---|
| 整个后台页可见 | `src/services/admin.js:15`（`requireAdmin`） | 每个 admin 接口都单独校验 `role === 'admin'`，非管理员一律 403 |
| 停用账号按钮 | `admin.js` `setUserStatus` | 不能停用自己、不能停用管理员；停用会**立即踢掉该用户所有会话** |
| 志愿者授权 | `admin.js:86-95` | 可多选存放点；移除时清空绑定并把角色改回 `student` |
| 重置密码 | `admin.js` `sendPasswordReset` | 管理员不直接设密码，而是**替用户发一封重置验证码** |

## 五、状态机（两套，别混）

| 类型 | 状态序列 | 定义位置 |
|---|---|---|
| 失物 `lost` | `open` → `reunited` → `archived` | `items.js:10`（`LOST_STATUS`） |
| 招领 `found` | `pending_storage` → `stored` → `claim_pending` → `ready_for_pickup` → `returned` → `archived` | `items.js:11`（`FOUND_STATUS`） |

**前端任何按状态显示/隐藏的逻辑，都要对照这两行。** #94 的 bug 就是没对照。

---

## 六、自查方法（给前端）

改任何"按条件显示"的代码前，问三个问题：

1. **后端在哪个函数里做同样的判断？** 找不出具体行 → 去读代码，别凭印象
2. **后端允许的状态/角色比我写的多还是少？** 多了 → 用户会看不到该有的按钮；少了 → 用户会点了报错
3. **改完之后，对应的 E2E / 冒烟会不会红？** 如果"改了也不红"，说明那条测试没测到真实规则

第 3 条是最灵的：#94 修完后 E2E 立刻红了，反而证明以前那条测试一直在测错的东西。
